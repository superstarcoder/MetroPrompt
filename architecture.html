Build

You type a goal. The Mayor lays the road grid, splits the map into 4-8 rectangles, and fans them out to Zone agents in parallel. Every change is a validated tool call, and each one is streamed to the browser as it lands.

effort low · thinking adaptive
Up to ~70 tool calls in a single build.

Tool layer▸

Schemas, handlers, and applyToolCall. Throws on overlap or OOB.
  • Models can't reliably emit a clean 50×50 ASCII grid, but they're good at structured tool calls. That's the core bet.
  • Grass-only rule: footprints must be all grass.
  • Every tool id is tracked, and unanswered ones are drained with errors so a session never wedges.

Simulate

The finished city gets populated. Citizens have decaying needs, pick a destination that serves them, and walk there. Fires break out and a truck is dispatched. All of this is plain TypeScript, with no LLM calls.

Needs decay, movement, fire response, run state.
  • stopSim() clears the citizens; endSim() just freezes the world. The report needs the second one.
  • fireLog is run-scoped, not saved with the city.
→spawn
Spawning▸
lib/sim/spawning.ts 54
Populates the city with citizens.
  • Gender is rolled first, then the name comes from that pool, which keeps the name, voice, and sprite in agreement.
  • Unisex names sit in both pools, which is why gender is stored rather than guessed from the name.
→each tick
Decisions▸
lib/sim/decisions.ts 176
Picks a destination, and records it when none exists.
  • A citizen's own home is excluded from the check, because a house serves hunger and counting it made the check always false.
  • Tiredness is excluded too: home beats a hospital for sleep, so that's not a gap.
→route
Pathfinding▸
lib/sim/pathfinding.ts 256
A* on a 4-connected grid, Manhattan heuristic.
  • Every step costs 1, so the Manhattan heuristic is admissible and consistent. Closed cells are never reopened.
  • Hand-rolled binary min-heap for the open set, and cells keyed as a single int (y * w + x) so the score maps stay flat.
  • No decrease-key: an improved cell is pushed again and stale copies are skipped on pop.
  • nearestEntryTile is a plain BFS out from a building's footprint. It turns a 3x3 building into the single point A* can target.
  • Grass is walkable, so an unreachable citizen is genuinely boxed in, usually ringed by road tiles.
→dispatch
Firetruck▸
lib/sim/firetruck.ts 178
Dispatch and response-time tracking.
  • Reuses the same findPath A*, just handed a drivability grid instead of a walkability one: roads, intersections and crosswalks only.
  • A record is written on arrival, not on dispatch.
  • Crosswalk is the only tile that's both walkable and drivable, so a sidewalk across a road cuts the truck off. The Mayor prompt covers this.

Voice: the audio loop
useVoiceAgent▸
components/city/useVoiceAgent.ts 539
The transport: socket, mic, playback, transcript. Shared by both agents.
  • Native WebSocket, not the SDK's. The SDK passes auth via a third constructor argument that browsers silently drop, so the UI just hangs on "Connecting…".
  • Auth rides the subprotocol: ['bearer', jwt].
  • Settings keys are snake_case. camelCase is ignored and quietly falls back to defaults.
  • Handlers are wired before the socket opens, since greeting audio can arrive within milliseconds.
↔WebSocket
16 kHz PCM
Voice Agent API▸
agent.deepgram.com/v1/agent/converse
Flux → Claude → Aura-2, plus turn detection and barge-in.
  • Flux needs version: 'v2' on the listen provider, or the model lookup fails.
  • No functions key is ever sent, so neither agent has tools.
→24 kHz PCM
Playback▸
scheduled buffers → analyser → speakers
Audio out, live visualizer, transcript paced to match.
  • Text arrives as one complete statement, not token deltas, so characters are metered against the audio clock to surface as they're spoken.
  • Barge-in freezes the text mid-sentence, which is what the citizen actually got to say, and flushes buffered audio.
  • Mute gates the mic send, not the track. No frames reach Deepgram, so barge-in is off by construction.

Schema

lib/all_types.tsx is the source of truth. Everything else reads it: the agent tools validate against it, the renderer draws from it, the simulation mutates it, and localStorage serialises it. 787 lines, no dependencies.

A grid and three lists
City▸
type City
The whole world in one plain object.
  • Separating the ground layer from the object lists is what makes rect fills cheap and object lookups direct.
  • day runs 1 to 7.
  • initCity(size) defaults to 500 and fills every cell with grass.
·
tile_grid▸
TileCode[][]
Ground layer, one char per cell.
Row-major, indexed [y][x]. Storing single chars is what makes the ASCII view a straight join instead of a conversion.
·
all_properties▸
Property[]
Buildings, anchored at their top corner.
A building is one entry with a width and height, not N grid cells. getPropertyAt and deletePropertyAt match against the whole footprint.
·
all_nature▸
Nature[]
Trees, flower patches, bushes. All 1x1.
Just a name, a position and an image. Nature blocks walkability but has no other behaviour.
·
all_citizens▸
Person[]
Empty until the simulation starts.
Populated by spawning.ts, cleared by stopSim(). This is why the report uses endSim() instead.

grass.yesnoDefault fill. The only surface buildings may be placed on.

Why this table is the important one TILE_META holds two booleans per tile, and those two booleans generate both grids the A* search runs on: walkability for citizens, drivability for fire trucks. Crosswalk being the only row with both set true is the entire reason the Mayor prompt has a rule about crossings.

Person and its sub-records
Person▸
type Person
Identity, needs, position, and an append-only history.
  • Three needs on a 1 to 10 scale, each with its own per-person decay rate drawn at spawn.
  • Every adult is an engineer; job holds the company name, matching an office's company_name. Children get null.
  • Four render-only fields (prev_location, tick_path, visual_position) let the renderer lerp between cells without the sim knowing about frames.
  • gender is optional because saves predate it. Always read it through citizenGender(), which falls back to a name hash.
·trips[]
Trip▸
type Trip
Where they went, how far, and when they arrived.
  • distance_tiles doubles as duration, since a citizen advances one cell per tick.
  • A missing arrived_tick means in progress or abandoned, so walkability stats filter on it being present.
  • This log is what grounds the citizen interviews. Without it they would invent their own history.
·unmet_wants[]
UnmetWant▸
type UnmetWant
The trips that never happened.
  • no_option: nothing in the city serves that need. Build something.
  • unreachable: it exists but there is no walkable route. Fix the roads.
  • Deduped by (need, reason) with first_tick, last_tick and a count, because idle citizens re-decide every tick.
  • Also optional, for the same back-compat reason as gender. Read as ?? [].
Helpers, and who reads the schema
Mutators▸
placeTile · placeTileRect · placeProperty · placeNature
They throw rather than clamp.
  • placeTileRect throws on out of bounds; placeProperty throws on overlap or out of bounds.
  • Failing loudly is what lets the agent tool layer report a real error back to the model instead of silently placing nothing.
  • deletePropertyAt matches any cell of a footprint, not just the anchor.
↔round trip
ASCII view▸
cityToAscii · asciiToCity · ASCII_LEGEND
The compact form agents read.
  • Buildings and nature are painted over the ground grid, so one char per cell shows everything.
  • Not lossless: ASCII drops sprite variants, so asciiToCity takes a strategy of 'default' or 'random'.
  • Use 'default' anywhere that runs during render, or the variants differ between server and client.
→consumed by
Agent side▸
lib/agent/{tools,observation}.ts
Validates tool calls, and renders the city as text.
The grass-only rule is enforced here, against TILE_META and the property footprints.
→
Client side▸
useCityScene.ts · cityStore.ts · renderConfig.ts
Draws it, saves it, and offsets the sprites.
Image arrays live in the schema file, but the variant roulette runs in the browser so the same city can look different across loads.
Two rules the schema enforces by construction No Math.random() at module level, or server and client disagree on sprite variants and React throws a hydration mismatch. Variant picking happens in effects and event handlers only. And new fields are added optional, since cities in localStorage predate them: gender and unmet_wants both went in that way.
